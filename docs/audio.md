# listening and recording

the phone can be the agent's ears as well as its eyes. recording uses the same link, pairing and sealing as the camera: the hub relays encrypted chunks and never hears anything.

## what the agent gets

| tool | use |
| --- | --- |
| `audio_record` | one clip, up to 60 seconds, returned as wav |
| `audio_listen_start` | start a continuous session; the phone buffers audio |
| `audio_listen_next` | pull the next chunk, default 10 seconds, max 30 |
| `audio_listen_stop` | stop the session and close the microphone |
| `audio_level` | measure rms/peak dbfs for a short window, without audio |

`audio_record` is for "what does this beep sound like" or "record the fan for ten seconds". the model receives one wav file plus duration and loudness.

`audio_listen_*` is for longer listening. `audio_listen_next` returns one complete wav chunk and the agent calls it again to keep listening. the phone keeps recording into a file while the model is busy, so a slow model does not lose the sounds in between. this is what makes listening effectively unlimited: the session has a length cap, but each chunk is small and the next call continues where the last one stopped. start a new session when the old one reaches its cap.

`audio_level` is a one-shot measurement like `audio_record`, so it replaces an open listening session. use it before starting a session, or expect to start again afterwards.

the agent should call `audio_listen_stop` when it is done. if it forgets, the microphone still stops when the agent disconnects or reconnects, and a new `audio_record` or `audio_listen_start` replaces the old session.

## format and limits

- mono 16-bit pcm in wav, 16 khz by default, 8–48 khz accepted
- every chunk is a complete wav file and can be played on its own
- one-shot clip: 100 ms to 60 s
- session chunk: 100 ms to 30 s
- session length: default 10 minutes, maximum 2 hours; `maxDurationMs: 0` records until stopped (or until the phone runs out of space)
- `audio_level`: 100 ms to 30 s
- levels are dbfs, floored at -100; `clipping` means a sample hit the int16 limit

a 10-second 16 khz chunk is about 320 kb. keeping chunks at 10–30 seconds keeps each tool reply usable by the model and keeps latency predictable.

## privacy

the microphone opens only when the agent asks. android, ios and the browser show a red recording indicator while a session is open. the phone stops recording when the agent leaves, when the socket drops, or when the app closes. like the camera, the microphone is shared by every hub connection on the phone, so one agent at a time can record.

audio is sealed end to end with the same aes-256-gcm session as photos. a rogue hub can drop chunks or refuse to relay, but it cannot hear them.

## cli

```bash
ambivalence listen -o clip.wav                # 5 seconds by default
ambivalence listen --duration 2m -o talk.wav # stream chunks into one file
ambivalence listen --duration 0 -o long.wav  # until Ctrl+C
ambivalence level --duration 2s
```

`listen` writes a canonical wav file. for clips up to 60 seconds it uses the one-shot path; longer recordings and `--duration 0` pull chunks and append their pcm, patching the header at the end. writing to stdout works too, but a pipe gets a zero-length header because the final size is not known.

## platform notes

- **android**: uses `AudioRecord` at 16 khz mono and spools pcm to the app cache. `RECORD_AUDIO` is requested next to the camera permission; the camera still works if you deny it.
- **ios**: uses `AVAudioRecorder` with linear pcm wav in the temporary directory. microphone permission is requested at launch. audio needs `NSMicrophoneUsageDescription` in `project.yml` and is regenerated by `xcodegen`.
- **browser**: uses `getUserMedia({audio:true})` and a script processor, resampling to 16 khz when a chunk is read. it needs https, like the camera.
- **fake host**: generates a two-tone test signal, useful for tests and for trying the tools without a phone.

## troubleshooting

`host does not support audio; update the phone app`: the phone did not advertise `audioVersion: 1` in `cameras`. update the app.

`microphone permission denied`: allow the microphone in the os settings. on android the permission prompt appears with the camera prompt on first launch; on ios it appears at launch.

`no such audio session`: the session ended, was replaced by a new recording, or the agent reconnected. start again with `audio_listen_start`.

the agent hears only silence: check `audio_level` first. if the level is near -100, the microphone is muted, covered, or the os routed input elsewhere.
